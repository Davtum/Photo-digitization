# Оцифровка фасадных фотоснимков: проектная спецификация

**Дата:** 2026-09-17
**Редакция:** 3 (переработана по итогам двух независимых рецензий; журнал изменений — раздел 21)
**Статус:** готов к декомпозиции в план работ

---

## 1. Задача

Дрон облетает здание и снимает фасады. Требуется по фотоснимку определить, какие элементы
присутствуют на фасаде (окна, двери, границы фасада), где именно они расположены и каковы их
размеры, и записать результат в структурированный файл с координатами в плоскости фасада.

Снимки поступают под произвольным углом и разного качества, поэтому геометрическое
выравнивание — обязательная часть задачи, а не опция.

## 2. Границы работы

**В объёме:**

- обработка одиночного фотоснимка фасада или его фрагмента;
- коррекция дисторсии объектива, перспективы и **параллакса заглублённых и выступающих
  элементов**;
- определение координат и габаритов элементов фасада;
- метрическая привязка с явной, проверяемой оценкой погрешности;
- участие оператора в цикле обработки;
- структурированный экспорт.

**Вне объёма (формат выхода не должен это блокировать):**

- построение 3D-модели здания;
- выявление и классификация повреждений;
- сшивка облёта в единую модель фасада;
- энергетический и конструктивный анализ.

Перечень случаев, признанных неприменимыми, — раздел 17.

### 2.1 Обозначения углов

В редакции 2 символ θ обозначал одновременно наклон камеры и угол луча в конкретной точке, что
породило противоречия. Разведено:

| Обозначение | Смысл |
|---|---|
| **θ_cam** | угол между оптической осью камеры и нормалью к плоскости фасада (наклон аппарата) |
| **θ(x, y)** | угол между лучом на точку (x, y) и нормалью к плоскости фасада |
| **θ_x, θ_y** | компоненты θ(x, y) в горизонтальном и вертикальном направлениях плоскости фасада |

Существенно: θ(x, y) ≠ 0 даже при строго фронтальной съёмке. Поле зрения камер класса DJI
Zenmuse L2 и Mavic 3 составляет 84° по диагонали (24 мм в эквиваленте), поэтому при θ_cam = 0
угол луча меняется от 0° в центре кадра до ≈ 42° в углу. Параллакс (раздел 5) управляется
именно θ(x, y), а не θ_cam.

### 2.2 Целевая точность

Формулируется статистически, раздельно по величинам и **по режимам работы**, поскольку бюджеты
различны (раздел 6).

| Величина | Режим | Цель | Условия |
|---|---|---|---|
| Габарит проёма по наружному контуру | `assisted` (кромки подтверждены оператором) | 1σ ≤ 10 мм, P95 ≤ 20 мм | локальный GSD ≤ 5 мм/px в худшей точке контура; масштаб от опорного размера; θ(x,y) ≤ 30°; камера откалибрована |
| То же | `auto` (без правки) | 1σ ≤ 25 мм | те же условия |
| Глубина заглубления `recess_mm` | `assisted` | 1σ ≤ 20 мм при θ_⊥ ≥ 15° | видимая грань откоса различима |
| Взаимное положение соседних элементов (в пределах ряда/колонны) | `assisted` | 1σ ≤ 12 мм | — |
| Абсолютное положение относительно начала координат фасада | `assisted` | 1σ ≤ 0.4 % расстояния, P95 ≤ 0.8 % | — |
| Систематическое смещение (bias) габарита | любой | \|bias\| ≤ σ_ref (раздел 11) | проверяется отдельно от разброса |

Изменения относительно редакции 2 и их причины:

- **Допуск на абсолютное положение ослаблен с 0.15 % до 0.4 %.** Прежнее значение было ниже
  нижней границы собственного бюджета остаточной невязки (0.2–0.5 %), то есть недостижимо по
  расчётам самой спецификации.
- **Введено взаимное положение соседних элементов** как отдельная величина. Именно оно
  определяет качество структурной регуляризации и большинство прикладных применений, и оно
  существенно точнее абсолютного, поскольку берётся как разность близких точек и не накапливает
  градиент невязки.
- **Допуск на габарит по внутреннему контуру снят.** Величина не наблюдаема однозначно
  (п. 5.5); вместо неё нормируется глубина заглубления.
- **Bias привязан к достижимой точности эталона.** Требование «≤ 5 мм» было непроверяемо
  эталоном с σ_ref 5–15 мм.

Требование к GSD относится к **худшему локальному** значению после ректификации: при наклонной
съёмке разрешение на дальней стороне кадра в 2–3 раза хуже, чем в центре.

### 2.3 Состав классов

Первая очередь максимально пересекается с публичными датасетами, что позволяет использовать
претрейн; вторая добавляется дообучением без изменения архитектуры.

**Очередь 1 (этапы 1–6):**

| Класс | Геометрия | Примечание |
|---|---|---|
| `window` | четырёхугольник | наружный контур по кромке в плоскости стены; атрибуты `mounting`, `edge_type` |
| `door` | четырёхугольник | включая входные группы; те же атрибуты |
| `reveal` | четырёхугольник | видимая грань откоса; **служебный класс**, носитель информации о глубине (раздел 5) |
| `facade_boundary` | полилиния | вертикальные рёбра, линия кровли, линия цоколя; атрибут выноса `offset_mm` |

`reveal` введён не как самостоятельная цель оцифровки, а как измерительный инструмент.

Атрибут `mounting`: `embedded` / `flush` / `protruding`. Разделение заимствовано у авторов
BFA-3D, которые развели `embedded window` и `protruding window` в разные классы, — независимое
подтверждение того, что способ установки значим и для распознавания, и для измерения.

Атрибут `edge_type`: `sharp_wall_edge` / `surround` / `cladding_edge` / `unknown`. Введён по
итогам рецензии: утверждение «наружная кромка свободна от параллакса» верно лишь при кромке,
лежащей в плоскости стены (п. 5.3).

**Очередь 2 (этап 7 и далее):** `balcony`, `floor_band` (межэтажные пояса), `shopfront`.
`floor_band` задаёт горизонтальную сетку фасада и повышает качество регуляризации (п. 4.3).

Навесное оборудование и материал стены в объём не входят.

### 2.4 Покрытие фасада одним кадром

Два ограничения действуют одновременно:

- по разрешению: 5280 px при GSD 5 мм/px дают 26.4 м;
- по углу: условие θ(x, y) ≤ 30° при типичном поле зрения ограничивает используемую полосу
  кадра примерно до 21.7 м при том же GSD.

Действует более жёсткое: **рабочая ширина одного кадра ≈ 21 м**, периферия кадра за пределами
углового условия используется для детекции, но не для измерений и помечается в `valid_mask`.

Фасады шире обрабатываются пофрагментно: каждый фрагмент — самостоятельный файл с
`coverage: "partial"`. Сшивка фрагментов — задача режима облёта (раздел 18).

## 3. Состояние области

### 3.1 Фотограмметрические измерения фасадов по одиночному снимку

Зрелая ветвь, решающая близкую задачу. Ordóñez, Martínez, Arias и соавторы (Automation in
Construction 17(5), 2008; Automation in Construction 19, 2010; Measurement, 2010) сочетают
одиночный снимок, лазерный дальномер и ориентацию по линии схода плоскости фасада, выполняют
распространение дисперсий по измерению и сообщают: относительную ошибку около **1 %** по
расстояниям и площадям (2008) и точность **11 мм для 95 % значений** (2010).

Два следствия для позиционирования настоящей работы, существенных и неприятных:

1. Заявленная нами цель (P95 ≤ 20 мм) **хуже** результата системы 2010 года. Претендовать на
   превосходство по точности на плоских элементах нельзя.
2. Их методы по построению работают с **плоскими** элементами фасада и не компенсируют
   заглубление проёма.

Отсюда честная постановка: на плоских элементах — паритет с известным уровнем при кратно
меньших трудозатратах за счёт автоматической детекции; на заглублённых — работа там, где
предшествующий метод неприменим.

К этой же ветви примыкает Single View Metrology (Criminisi, Reid, Zisserman, IJCV 40(2), 2000):
по линии схода опорной плоскости и точке схода несопряжённого направления вычисляются
расстояния между плоскостями, параллельными опорной. Измерение глубины заглубления проёма —
частный случай этой конструкции (п. 5.4).

### 3.2 Ректификация

Устоявшийся подход: детекция отрезков (LSD) → группировка в пучки → оценка двух точек схода в
предположении Manhattan-структуры → гомография. Метрическая ректификация сохраняет углы и
отношения длин, но не восстанавливает абсолютный масштаб.

Вопрос о пользе ректификации **для качества детекции** в литературе решён противоречиво:

- Facade R-CNN (arXiv 2205.05912, прил. E.2, табл. 9, RueMonge2014): базовая модель 70.37 mIoU
  и 87.5 % точности против 69.01 и 87.26 с предварительной ректификацией; вывод авторов — «the
  rectification strategy is not able to bring improvement compared to the baseline»;
- Texture2LoD3 (CVPRW 2025): ректификация даёт прирост IoU, у SegFormer до +10 %;
- Neuhausen и König (2018), до эпохи глубокого обучения: ректификация улучшает детекцию.

Существуют и альтернативные стратегии работы с перспективой: модуль transconv в Facade R-CNN
(свёртки со сдвинутыми ядрами), обучаемая ректификация внутри детектора (QuadWindow, 2025),
парный alignment-loss (arXiv 2604.09260), симметрийные функции потерь (DeepFacade).

### 3.3 Детекция элементов фасада

Три поколения: семантическая сегментация (DeepFacade, SOLOv2, SegFormer) — маски без объектов;
instance-детекция (Mask R-CNN, Facade R-CNN с четырёхугольными боксами, 74.34 mIoU на
RueMonge2014); детекторы под мультивидовую съёмку (BFA-YOLO, +1.8 п.п. mAP@0.5 на BFA-3D и
+2.9 п.п. на Facade-WHU).

Ограничения, существенные для планирования:

- У BFA-YOLO опубликованы код и данные, но **нет весов и нет лицензии** (в репозитории
  `license: null`, отсутствует LICENSE и файлы весов); набор распространяется через Baidu Pan.
  В продукте использовать нельзя; для сравнения — воспроизводить обучением, с учётом
  юридической неопределённости.
- BFA-3D — **синтетический рендер с 3D-моделей**: камера на 10 м выше ближайшей застройки,
  поворот с шагом 60° от 0° до 300°, случайный наклон 0–30°, 1240 изображений 1200×1200, 41 551
  объект. Это не съёмка.

Zero-shot детекция проёмов: Yarroudh и соавторы (ISPRS Archives XLVIII-2-W8-2024) сообщают для
Grounding DINO на фасадных изображениях **61.5 %** (40 обнаруженных окон из 65). Это первый и
пока единственный найденный ориентир; уровень невысокий — как предразметка означает, что
примерно каждый третий проём оператору придётся создавать вручную.

### 3.4 Структурная регуляризация

Известные решения — грамматики, Spatial Pattern Templates, учёт трансляционной симметрии,
бинарное целочисленное программирование, парный alignment-loss.

Зафиксированное ограничение (arXiv 2604.09260): рост веса регуляризации снижает mAP, а на
фасадах со смешанными типами окон в одном ряду приводит к растяжению или сжатию границ; при
больших весах крупные и очень мелкие окна перестают детектироваться. Это определяет решение
п. 4.3.

Метрика регулярности той же работы (сумма MSE между бинарной маской и её аппроксимациями ранга
k = 1..25 по SVD) наказывает корректный результат на действительно нерегулярных фасадах, что
отмечают сами авторы. Применяется с оговоркой и не как единственная.

### 3.5 Метрический масштаб

Монокулярные модели глубины как источник масштаба **непригодны**. По бенчмарку AerialMetric
(arXiv 2606.29716) на снимках БПЛА zero-shot AbsRel составляет: UniDepthV2 17–31 %, MoGe-2
27–71 %, Depth Pro 92–98 %. Отказ зафиксирован с обоснованием.

### 3.6 Целевой интерфейс отрасли

Реконструкция LoD3 CityGML (Scan2LoD3, Texture2LoD3, CM2LoD3) и генерация as-built BIM в IFC.

Оговорка: широко цитируемого «порога 10 см для LoD3» не существует. В спецификации CityGML 2.0
для LOD3 задана точность 3D-точки 0.5 м и обобщение «объекты как реальные элементы»; у Biljecki
и соавторов (2016) LOD3.3 определён как элементы крупнее 0.2 м. Число 10 см относится к
правилам моделирования конкретного набора TUM2TWIN и отраслевой нормой не является.

### 3.7 Вклад настоящей работы

Формулировки сужены по итогам поиска прецедентов. Прежние заявки редакций 1–2 были завышены.

**Вклад 1. Измерение глубины заглубления проёма по видимой грани откоса на одиночном снимке в
составе автоматического конвейера детекции, с коррекцией параллакса внутреннего контура и
валидацией точности как функции угла визирования.**

Что уже известно и на что нельзя претендовать:

- общий принцип измерения расстояния между параллельными плоскостями по одиночному виду —
  Criminisi и соавторы (2000); предлагаемая формула есть его частный случай в ректифицированных
  координатах при откалиброванной камере;
- Lee и Nevatia (CVPR 2004, «Extraction and Integration of Window in a 3D Building Model from
  Ground View Images») в аннотации заявляют: глубина извлечённых окон вычисляется автоматически
  «using window classification information and image line features», и одиночного наземного
  снимка для этого достаточно. Полный текст закрыт (IEEE), свободной копии не найдено —
  см. раздел 20. Существенная деталь: упоминание «window classification information» допускает,
  что глубина **назначается по типу окна**, а не измеряется; в этом случае пересечение с
  настоящей работой минимально. Различить два прочтения по аннотации нельзя;
- Bacharidis и соавторы (2020) получают ту же величину через обученную монокулярную глубину —
  иной принцип;
- Becker (2011) моделирует глубину окна, но из наземного лидара.

Остаётся защитимым: замкнутая форма через ширину откоса и компоненту угла визирования,
применённая к съёмке с БПЛА; включение поправки в конвейер детекции; бюджет погрешностей и
экспериментальная оценка границ применимости; независимый второй канал по тени (п. 5.7).

**Вклад 2. Контролируемое сравнение предварительной ректификации с парным alignment-loss
(arXiv 2604.09260) на одном детекторе и одних данных, по критерию метрической точности, а не
качества сегментации.**

Что уже известно: ablation «ректификация против её отсутствия» по качеству сегментации
выполнялся и дал противоречивые результаты (п. 3.2); существуют архитектурные альтернативы
(transconv, QuadWindow). Работа arXiv 2604.09260 обучена и оценена на CMP, то есть на **уже
ректифицированных** данных, и с ректификацией себя не сравнивала.

Остаётся свободным: сопоставление именно этих двух стратегий, и — существеннее — сопоставление
по **метрической точности в миллиметрах**, тогда как все известные сравнения оценивали mIoU и
mAP. Это другой критерий, и для измерительной задачи он единственно релевантный.

**Вклад 3. Публикуемые трудозатраты оператора для производственного конвейера детекции проёмов
по снимкам с БПЛА: время на фасад, число правок, доля автоматических предсказаний, принятых без
изменения.**

Что уже известно: Musialski и соавторы (2012) публикуют ровно эту пару метрик для
интерактивного моделирования фасадов (например, для фасада F1: 960 правок и 24.0 мин вручную
против 110 правок и 6.75 мин с их инструментом), Wu и соавторы (2014) сообщают 5–30 мин на
фасад, Pantoja-Rosero и соавторы (Automation in Construction, 2024) подают сокращение времени
разметки как результат для сегментации фасадов, существуют общие работы по HITL-разметке.

Остаётся: конкретный набор метрик для нейросетевой детекции проёмов на снимках с дрона и
сравнение с SAM-ассистированной разметкой как базовым уровнем. Формулировка «практически не
публикуется» заменена на «публикуется редко и не для этого класса систем».

## 4. Архитектура

Двенадцать модулей с узкими интерфейсами.

| Модуль | Ответственность | Вход → выход |
|---|---|---|
| `io` | Загрузка, EXIF, нормализация | файл → `Image`, `CameraMeta` |
| `quality` | Оценка пригодности снимка | `Image` → `QualityReport` |
| `calib` | Дисторсия; внутренние параметры | `Image`, `CameraMeta` → `Image`, `K`, `DistCoeffs` |
| `plane` | Плоскость фасада и поза камеры | `Image`, `K` → `Homography`, `CameraPose`, `PlaneConfidence` |
| `rectify` | Фронто-параллельный вид | `Image`, `H` → `RectifiedImage`, `ValidMask`, `LocalGSD`, `AngleMap` |
| `scale` | Метрическая привязка | `ScaleRequest` → `ScaleEstimate` |
| `detect` | Предразметка | `RectifiedImage` → `Candidate[]` |
| `annotate` | Правка и подтверждение оператором | `Candidate[]` → `Element[]` |
| `depth` | Глубина заглубления, коррекция параллакса | `Element[]`, `CameraPose` → `Element[]` с `recess` |
| `regularize` | Предложения по выравниванию | `Element[]` → `Proposal[]` |
| `assemble` | Сборка модели, px → мм, свод погрешностей | всё выше → `FacadeModel` |
| `export` | Сериализация | `FacadeModel` → JSON / DXF / IFC |

`rectify` дополнительно выдаёт `AngleMap` — поле θ_x(x, y) и θ_y(x, y), необходимое модулю
`depth`. В редакции 2 этого выхода не было, что делало векторную коррекцию невыполнимой.

### 4.1 `quality` — отбраковка, а не улучшение

Генеративный деблюр синтезирует границы, которых в кадре не было, а измерение выполняется
именно по границам: результат — визуально убедительный снимок и уверенно неверные миллиметры.

Модуль работает как **шлюз**: оценивает резкость (вариация лапласиана, ширина размытого края,
MTF50-прокси), экспозицию, локальный GSD, углы θ(x, y) по полю кадра и долю кадра,
удовлетворяющую угловому условию; выдаёт вердикт `ok` / `degraded` / `reject`.

Пороги калибруются на данных этапа 1: собирается выборка снимков с известной точностью
измерения, пороги выбираются так, чтобы вердикт `ok` соответствовал выполнению допуска п. 2.2.
Это задача с критерием, а не свободный параметр.

Деблюр — в исследовательском бэклоге; критерий приёмки — снижение RMSE габаритов, а не
улучшение визуального качества.

### 4.2 `plane` — уверенность, поза камеры, внутренние параметры

Модуль возвращает метрику доверия: число отрезков, поддержавших каждую точку схода; остаточную
невязку; отклонение направлений от ортогональности; долю площади кадра, покрытую
поддерживающими отрезками.

Модуль обязан выдавать **позу камеры относительно плоскости фасада**: без неё невозможно
вычислить θ_x и θ_y и, следовательно, коррекцию параллакса (раздел 5).

**Как именно получается поза.** Формулировка редакции 2 («поза получается из `H` и `K`») верна,
но недоговаривает главное и потому допускает неверную реализацию. Гомография, построенная по
двум точкам схода, есть гомография **чистого поворота** и трансляции не содержит; извлечь из неё
положение камеры напрямую нельзя. Опорная точка F восстанавливается иначе:

- две точки схода дают направления осей плоскости в системе камеры `d₁`, `d₂`, откуда направление
  нормали `d₃ = d₁ × d₂`;
- луч, идущий из центра камеры вдоль нормали, пересекает Π ровно в точке F, а все точки этого
  луча имеют один и тот же образ — **точку схода направления нормали** `v₃ = K·d₃`;
- следовательно `F = H · v₃` с последующим переводом в миллиметры по масштабу.

Проверено численно на трёх различных позах камеры: невязка восстановления F не превышает
10⁻¹² мм. Расстояние до плоскости `C_z` из точек схода не извлекается и задаётся масштабом:
`C_z = f · (мм на пиксель)`.

**Внутренние параметры.** Две точки схода плюс ортогональность позволяют оценить фокусное
расстояние, но при малой перспективе оценка вырождается. Ошибка фокусного ε искажает отношение
сторон ректифицированного изображения. Проверено численно (синтетическая камера, плоскость с
известным квадратом, ректификация по ошибочному f):

| θ | 10° | 15° | 20° | 30° | 45° |
|---|---|---|---|---|---|
| Искажение при ε = 2 % | 0.061 % | 0.135 % | 0.235 % | 0.501 % | 0.995 % |
| Оценка ε·sin²θ | 0.060 % | 0.134 % | 0.234 % | 0.500 % | 1.000 % |

Формула **ε·sin²θ** подтверждена для наклона по одной оси. В редакции 2 фигурировала
ε·sin²θ/cos θ, завышавшая эффект до 40 %. При наклоне по двум осям одновременно простая формула
неточна (расчёт даёт как большие, так и заметно меньшие значения), поэтому в бюджете
используется как оценка сверху, а точное значение вычисляется из позы.

Отсюда: камеры собственного парка калибруются **один раз по мишени**; для чужих камер фокусное
берётся из EXIF с соответствующим флагом; в протокол включён ablation «EXIF против калибровки».

**Критерий инлайера задаётся в пикселях, а не в нормированных единицах.** Это оказалось
определяющим для точности всей оценки. При нормировке дистанции на длину вектора точки схода
фактический допуск в пикселях растёт неограниченно по мере её удаления: при типичных параметрах
он достигал 3253 пикселей, и инлайерами становились все отрезки подряд без исключения. Следствия
были двоякими: оценка смещалась, а метрика доверия выдавала 0.97–1.00 с пустым списком причин на
входах, где точки схода не существует вовсе.

После перевода критерия в пиксели погрешность оценки против истинной точки схода `K · (R_wc · d)`
снизилась с 0.671° до **0.005°**, то есть более чем на два порядка, а невязка стала измеряться в
действительных пикселях: 0.18 px вместо безразмерной величины, умноженной на размер кадра.

**Доверие определяется обусловленностью пучка, а не только покрытием.** Доля поддержавших
отрезков сама по себе ничего не говорит: на почти параллельном пучке её можно довести до единицы.
Разделяющей величиной служит обусловленность — отношение веера направлений к угловому шуму.
Измерено: реальные сцены дают 53–692, вырожденный пучок почти параллельных прямых — 2.8–6.8.
Порог принят равным 15.

**Смещение от фрагментации отрезков пренебрежимо.** Детектор дробит длинную кромку на обломки, и
в голосовании такая прямая получает вес по числу обломков, а не по длине. Измерение при
исправленном критерии инлайера, на 2000 гипотез и четырёх ракурсах: разница между сырым и слитым
наборами составляет **0.0003°** в среднем по восьми пучкам, причём слияние выигрывает в пяти
случаях из восьми — то есть неотличимо от случайности. Взвешивание по длине измеримо хуже:
0.0570° против 0.0358°.

Слияние коллинеарных отрезков поэтому не вносится. Ранее измеренное смещение 0.393°, которое
приписывалось фрагментации, полностью объясняется дефектом критерия инлайера: на тех же исходных
условиях исправленный оценщик даёт 0.0055°.

**Ручной fallback.** Четыре точки, объявленные прямоугольником, оставляют одну неизвестную —
отношение сторон; четыре точки произвольного четырёхугольника не дают ничего. Поэтому оператор
указывает четыре точки **и** одно из: отношение сторон, два размера в миллиметрах, либо
подтверждение, что камера откалибрована и направления ортогональны. Реализуются все три.

### 4.3 `regularize` — предложения, а не принуждение

Система кластеризует элементы по рядам и колоннам и показывает оператору конкретные варианты:
«6 окон ряда 3 можно выровнять, максимальное отклонение 12 мм — применить?». Решение принимает
оператор. Это снимает риск порчи нерегулярных фасадов, не требует подбора веса регуляризации и
оставляет результат аудируемым через поле `origin`.

Автоматический режим реализуется **только для эксперимента** (п. 13.4) и в производственный
конвейер не выводится.

Порядок внутри сессии: масштаб задаётся **до** первого предложения; до этого момента
предложения формулируются в пикселях либо подавляются.

### 4.4 `assemble` — единая точка сведения погрешностей

Перевод пикселей в миллиметры и расчёт итоговых σ выполняются в одном месте. Это необходимо,
потому что погрешности коррелированы: ошибка масштаба **общая для всех элементов фасада** и не
усредняется при агрегировании. Реализация — линеаризованное распространение с якобианами по
цепочке раздела 6, с проверкой методом Монте-Карло на синтетике.

## 5. Геометрическая модель: параллакс и глубина заглубления

Центральный раздел. Все формулы выведены и проверены численно построением лучей; результаты
проверки — в п. 5.9.

### 5.1 Постановка

Плоскость фасада Π: Z = 0. Камера C = (C_x, C_y, C_z), C_z > 0. Точка P = (P_x, P_y, −d) на
глубине d за плоскостью (d > 0 — заглубление, d < 0 — вынос). **F = (C_x, C_y)** — проекция
камеры на Π по нормали (далее «опорная точка»).

### 5.2 Смещение: знаковая векторная форма

Луч C → P пересекает Π в точке P′. Смещение относительно ортогональной проекции P на Π:

```
δ = P′ − P_xy = (C_xy − P_xy) · d / (C_z + d)
```

Отсюда:

- **модуль:** |δ| = d · tan θ, где θ — полный угол луча к нормали. Эта часть редакции 2 верна;
- **направление:** для заглублённых элементов (d > 0) смещение направлено **к опорной точке F**,
  для выступающих (d < 0) — **от неё**. В редакции 2 направление было указано наоборот, что при
  реализации дало бы удвоенную погрешность (до 170 мм при θ = 30°, d = 150 мм);
- **компоненты:** δ_x = (C_x − P_x)·d/(C_z + d) = −d·tan θ_x, аналогично δ_y.

| Глубина d | θ = 5° | 15° | 30° | 45° |
|---|---|---|---|---|
| 150 мм | 13 мм | 40 мм | 87 мм | 150 мм |
| 300 мм | 26 мм | 80 мм | 173 мм | 300 мм |

Допуск 20 мм превышается при d = 150 мм уже при θ ≈ 7.6°, при d = 300 мм — при θ ≈ 3.8°.
Это **смещение**, а не разброс: оно не усредняется по выборке и складывается с разбросом
линейно, а не в квадратуре.

**Коррекция.** Истинное положение точки, наблюдаемой в P′ при известной глубине d:

```
P_true = F + (P′ − F) · (C_z + d) / C_z
```

### 5.3 Измеряемая кромка

Наружная кромка проёма — линия пересечения плоскости стены и плоскости откоса — **лежит в Π и
свободна от параллакса по построению** (проверено: смещение 0.000 мм во всех прогонах). Отсюда
определение, обязательное для разметки, детектора и процедуры извлечения эталона:

> Измеряемой кромкой проёма считается линия пересечения плоскости стены и плоскости откоса.
> В схеме фиксируется полем `edge_reference: "wall_plane"`.

Следовательно, параллакс искажает не столько геометрию, сколько **идентификацию кромки**: если
разметчик, детектор или процедура извлечения эталона локализуют внутреннюю раму вместо края
стены, возникает систематическая ошибка ровно d·tan θ.

**Скрытые допущения**, при нарушении которых утверждение неверно: стена вокруг проёма лежит в
Π, и кромка представляет собой острое ребро. Нарушается при наличниках и обрамлениях (вынос
20–80 мм), скруглённой или снятой фаске четверти, системах наружного утепления с накладными
откосами, навесных вентилируемых фасадах (плоскость облицовки не совпадает с плоскостью
проёма), проёмах в заглублённых панелях и лоджиях. Ошибка равна выносу обрамления, умноженному
на tan θ, и не обнаруживается: кромка выглядит чёткой, оператор её подтверждает.

Поэтому введён атрибут `edge_type`. При значении `surround` или `cladding_edge` элемент
обрабатывается как выступающий (п. 5.6) и требует `offset_mm`.

### 5.4 Оценка глубины: компонентная формула

**Это место было ошибочным в редакции 2 и составляло принципиальный дефект документа.**

Видимая ширина откоса, измеренная **поперёк его ребра**, равна не полному смещению, а его
компоненте в направлении нормали к ребру. Для вертикального откоса (левый или правый) это
горизонтальная составляющая; вертикальная составляющая сдвигает ребро вдоль откоса и на ширину
не влияет:

```
w_reveal = d · |u| / (C_z + d)
```

где `u` — проекция вектора от опорной точки F к кромке проёма на единичную нормаль `n̂` к ребру
откоса в плоскости Π. Отсюда **замкнутая форма**, которая и подлежит реализации:

```
d = w_reveal · C_z / (|u| − w_reveal)
```

Формулировка редакции 3 (`d = w / |t · n̂|`, где `t = (tan θ_x, tan θ_y)`) эквивалентна ей при
вычислении `t` на **внутреннем** ребре, но неявна: угол зависит от искомой глубины. Замкнутая
форма снимает эту неявность и не требует итераций. Эквивалентность проверена алгебраически и
численно (совпадение до 1e-12 на неосевых нормалях).

В частных случаях `u` есть горизонтальное смещение для вертикального откоса и вертикальное —
для перемычки.

Скалярная запись редакции 2 (`d = w / tan θ` по полному углу) занижает глубину в
tan θ / |t·n̂| раз. Численно (проверено):

| θ_x | θ_y | Истина | Скалярная формула | Занижение |
|---|---|---|---|---|
| 10° | 30° | 150 мм | 43.81 мм | **в 3.4236 раза** |
| 5° | 25° | 150 мм | 27.66 мм | **в 5.4229 раза** |
| 15° | 15° | 150 мм | 106.07 мм | в 1.4142 раза |
| 10° | 0° | 150 мм | 150.00 мм | верно |

Значения в таблице редакции 3 (3.45 и 43.5 мм в первой строке) относились к углам 9.86° и
29.84°: в черновой проверке камера вставала не точно на заданные углы, а подпись утверждала
10° и 30°. Приведённые здесь величины вычислены аналитически как `tan θ / |t·n̂|` и независимо
подтверждены при ревью реализации.

Худшие случаи — малый горизонтальный угол при большом вертикальном, то есть **штатный ракурс
дрона**, висящего напротив фасада выше или ниже проёма. Отказ был бы молчаливым.

**Где брать угол.** Вопрос снимается замкнутой формой: она выражена через непосредственно
измеримые `w`, `|u|` и `C_z` и угла не содержит вовсе. Прежняя оговорка о том, что при расчёте
по наружной кромке глубина занижается в отношении C_z/(C_z + d) — примерно на 1.5 % при
расстоянии 10 м, — относилась к неявной записи и более не актуальна для вычисления самой
глубины. Она остаётся существенной для бюджета погрешности, см. п. 6.2.

**Порог применимости** θ_min применяется к компоненте |t·n̂|, а не к полному углу, и по расчёту
п. 6.2 составляет θ_⊥ ≥ 15°. Ниже порога глубина не измеряется: при `|u| → w` замкнутая форма
неограниченно растёт, и без явной проверки система вернула бы физически бессмысленное значение
без признака неисправности.

### 5.5 Видимость граней и определение внутреннего контура

Вертикальный откос виден на **дальней от опорной точки F** стороне проёма. Если F лежит вне
диапазона проёма по X (обычный случай), виден ровно один вертикальный откос. Одновременно
видна одна горизонтальная грань — перемычка либо подоконная часть, в зависимости от знака
(P_y − C_y). Типовая наблюдаемая область — L-образная.

**Ближняя грань не наблюдаема.** Внутреннее ребро на ближней к камере стороне проецируется за
плоскость стены и оказывается закрытым (проверено: при кромке x = 3500 мм ребро проецируется в
x = 3463 мм). Следовательно на ближней стороне видимая граница проёма тождественна наружной
кромке.

Отсюда конструктивное определение, отсутствовавшее в редакции 2:

> **Внутренний контур** — четырёхугольник в плоскости, параллельной Π и отстоящей от неё на
> `recess_mm`, ограниченный внутренними рёбрами откосов. На сторонах, где грань откоса не
> наблюдаема, его положение не измеряется, а вычисляется из наружного контура и `recess_mm`,
> и помечается как `derived`.

Практическое уточнение: по ГОСТ 30971 оконная коробка в проёмах с четвертью заходит за
четверть не менее чем на 10 мм, то есть снаружи рама по контуру не видна вовсе, и наблюдаемая
внутренняя граница — ребро четверти. Величина `recess_mm` определяется как глубина **до ребра
четверти**, а не до плоскости рамы; для задач LoD3 это различие существенно и фиксируется полем
`recess.datum`.

### 5.6 Выступающие элементы

Для карниза, цоколя, выступающих окон, подоконников и обрамлений d < 0 и **видимая кромка не
лежит в Π**; свободной от параллакса кромки у них нет. Такие элементы несут обязательное поле
`offset_mm` (измерено либо принято типовое), коррекция вносится по формуле п. 5.2, а
погрешность увеличивается на неопределённость выноса. При отсутствии оценки выноса габарит
выдаётся без метрической интерпретации.

### 5.7 Второй канал: тень откоса

Добавлен по итогам рецензии. Ширина тени, отбрасываемой откосом на раму или стекло, равна
глубине, умноженной на тангенс угла между направлением на Солнце и нормалью к фасаду. Положение
Солнца вычисляется по времени съёмки (EXIF), координатам (телеметрия) и азимуту фасада (из позы
камеры и ориентации аппарата).

Ценность канала в том, что он **не зависит от угла визирования**: он работает и при θ → 0, где
метод откоса вырождается. Два канала вместе покрывают весь диапазон и проверяют друг друга;
расхождение между ними — сигнал о нарушении допущений (скошенный откос, обрамление, ошибка
позы).

Ограничения: требуется прямое солнечное освещение и различимая тень; при фасаде в
самозатенении канал недоступен. Реализуется на этапе 4 после базового канала.

### 5.8 Проверка согласованности

В редакции 2 предлагалось выявлять скошенные откосы по расхождению оценок глубины **с двух
сторон одного проёма**. Это неверно: как показано в п. 5.5, одновременно видны вертикальная и
горизонтальная грани, конструктивная глубина которых различается закономерно — подоконная
часть имеет уклон и отлив (требование ГОСТ 30971), перемычка может иметь четверть иного
размера. Проверка сравнивала бы разные величины.

Корректные проверки:

1. между **соседними однотипными проёмами одного ряда** — глубина должна совпадать;
2. между **каналом откоса и каналом тени** (п. 5.7);
3. по **согласованности с типовым значением** для класса здания.

Расхождение помечается флагом `consistency`, значение `suspect` понижает доверие к `recess`.

### 5.9 Протокол численной проверки

Все утверждения раздела проверены прямым построением лучей на синтетической сцене (плоскость
Z = 0, камера на 10 м, заглубление 150 мм) и подтверждены: нулевое смещение наружной кромки;
совпадение |δ| с d·tan θ; коэффициенты занижения скалярной формулы; направление смещения к
опорной точке; окклюзия ближнего внутреннего ребра. Скрипт проверки включается в репозиторий
как регрессионный тест этапа 0, с обязательными случаями: знак смещения, двухосевой угол,
окклюзия.

## 6. Бюджет погрешностей

### 6.1 Габарит по наружному контуру

Ширина 1500 мм, локальный GSD 5 мм/px, 1σ.

| Источник | Режим `assisted` | Режим `auto` |
|---|---|---|
| Локализация двух кромок, √2·σ_px·GSD | σ_px 0.5–1 → 3.5–7 мм | σ_px 2–3 → 14–21 мм |
| Масштаб от опорного размера | 2.1–4.2 мм | 2.1–4.2 мм |
| Остаточная проективная невязка | 3–7 мм | 7–15 мм |
| Ошибка фокусного (ε·sin²θ, ε = 2 %, без калибровки) | 0 при калибровке | 7.5 мм при θ=30°, 15 мм при θ=45° |
| Остаточная дисторсия | 2.5–5 мм | 2.5–5 мм |
| Неплоскостность стены (±20–50 мм, эффект = отклонение·tan θ) | 2–7 мм при θ≤8°; **11.5–29 мм при θ=30°** | то же |
| **Параллакс (смещение, не разброс)** | 0 при корректной кромке и `edge_type = sharp_wall_edge` | 10–45 мм при ошибке идентификации кромки |

RSS режима `assisted`: **6.0–13.7 мм** при θ ≤ 8°; при θ = 30° верхняя граница возрастает до
≈ 32 мм за счёт неплоскостности. В редакции 2 строка неплоскостности была посчитана только для
малых углов, что занижало бюджет вчетверо для заявленного режима.

Следствие, которое нужно принять: **цель 1σ ≤ 10 мм достижима не во всём заявленном диапазоне
углов, а при θ ≲ 15–20°.** Диапазон до 30° сохраняется как рабочий, но с ухудшенной точностью,
и `meets_tolerance` вычисляется по фактическому углу, а не по режиму.

### 6.2 Глубина заглубления

**Независимые переменные.** Глубина вычисляется по замкнутой форме п. 5.4:

```
d = w · C_z / (|u| − w)
```

Её аргументы — ширина откоса `w`, расстояние от опорной точки до кромки `|u|` и дистанция до
плоскости `C_z`. Компонента угла `θ_⊥ = arctg(|u| / (C_z + d))` независимой переменной **не
является**: она сама зависит от искомой глубины. Поэтому бюджет строится на точных частных
производных замкнутой формы:

```
∂d/∂w   =  C_z · |u| / (|u| − w)²
∂d/∂|u| = −w · C_z  / (|u| − w)²
∂d/∂C_z =  w / (|u| − w)   ( = d / C_z )
```

σ складывается от трёх вкладов. Производные проверены аналитическим выводом и центральными
разностями **самой реализации** `reveal_depth` по каждому независимому аргументу; сходимость
rel ≤ 3·10⁻¹¹.

**Малоугловое приближение и его смещение.** Записи редакции 3

```
σ_d = σ_w / |t·n̂|          σ_d / d = 2σ_θ / sin 2θ_⊥
```

остаются верными как приближение, но **занижают** чувствительность: первая ровно в `1 + d/C_z`,
вторая в `cos²θ_⊥ / cos²φ`, где `φ = arctg(|u| / C_z)`. При d = 150 мм, C_z = 10 м, θ_⊥ = 30°
это 1.015 и 1.0076. Численно: ∂d/∂w равна 1.7580 против приближённых 1.7321; относительный вклад
позы 2.3269 против 2.3094.

Полтора процента сами по себе невелики, но смещение направлено **в опасную сторону** — заявленная
точность оказывается выше фактической. Приближение допустимо для оценок на бумаге и недопустимо
в коде, выдающем σ потребителю.

Утверждение редакции 3 о том, что обе составляющие суть частные производные одной функции
`d(w, θ_⊥)`, **неверно** и снято: `θ_⊥` не является независимой переменной.

**Перевод угловой погрешности позы.** Функция бюджета принимает `σ_u` в миллиметрах, а не угловую
величину. Перевод выполняет вызывающий код:

```
σ_u = C_z · sec²φ · σ_θ,    φ = arctg(|u| / C_z)
```

Множитель `sec²φ` неочевиден и при опорной геометрии заметен: σ_θ = 0.5° даёт σ_u ≈ 117 мм.
Допуски п. 2.2 заданы в градусах, поэтому перевод обязателен и записывается здесь явно — это
ровно то место, где ошибка проходит незамеченной.

**Допущение о независимости.** Сложение по квадратичной сумме предполагает независимость `w`,
`|u|` и `C_z`. В действительности `|u|` и `C_z` происходят из одной оценки позы, а `w` и `|u|`
извлекаются из одного ректифицированного снимка — все три в общем случае коррелированы.
Существенно, что корреляция **не консервативна**: при положительной корреляции RSS даёт нижнюю
оценку σ. При интеграции с реальной оценкой позы (раздел 13, этапы сборки конвейера) требуется
полная ковариационная матрица; до тех пор заявляемая σ помечается как оценка при допущении
независимости.

**Порог применимости.** Обе составляющие растут при малых углах: при GSD 5 мм/px и ошибке в один
пиксель вклад ширины составляет 57 мм при θ_⊥ = 5°, 19 мм при 15° и 8.7 мм при 30°. Порог
выбирается так, чтобы суммарная σ_d удовлетворяла п. 2.2, и составляет **θ_⊥ ≥ 15°**. Проверка
порога выполняется в самой функции оценки глубины, а не отдаётся вызывающему коду: при `|u| → w`
замкнутая форма растёт неограниченно, и без проверки система вернула бы физически бессмысленное
значение без признака неисправности.

| Приоритет | Источник | Типовая σ | Достигает допуска? |
|---|---|---|---|
| 1 | Оператор указал известный размер | 0.14–0.28 % → 2.1–4.2 мм | **Да** |
| 2 | Фотограмметрия облёта | ~2 мм | Да (раздел 18) |

### 6.4 Положение

Остаточная невязка даёт градиент по полю: при 0.2–0.5 % на фасаде 25 м это 50–125 мм на дальнем
краю относительно начала координат — отсюда допуск п. 2.2 на абсолютное положение. Взаимное
положение соседних элементов свободно от накопленного градиента и нормируется отдельно.

### 6.5 Где выполняется измерение

Ректифицированное изображение интерполировано и на дальней стороне наклонного кадра
апсемплировано. Субпиксельное уточнение кромки выполняется **в исходном снимке** с переносом
через `H`. Ректифицированное изображение служит для детекции, работы оператора и визуализации,
но не является конечным носителем измерения.

## 7. Система координат

Начало — левый нижний угол фасада либо, если он не в кадре, опорная точка оператора
(`coverage: "partial"`). Ось X вправо вдоль фасада, ось Y вверх, единицы — миллиметры.

Для каждого элемента сохраняются координаты в миллиметрах, координаты в пикселях каждого
исходного снимка, матрица `H` и параметры камеры — то есть связь с исходным снимком обратима.
Это обязательно: на последующих этапах к элементам будут привязываться повреждения, выявленные
на конкретных кадрах.

## 8. Оператор и цикл накопления данных

1. Система полезна с первого дня, до появления автоматики.
2. Каждый обработанный фасад становится размеченным примером.
3. Ручная оцифровка задаёт эталон для измерения точности автоматики.

Автоматика встраивается как предразметчик с интерфейсом `RectifiedImage → Candidate[]`:
**v0** — zero-shot (Grounding DINO + SAM2), ожидаемый уровень около 61 % обнаружения по
опубликованным данным (п. 3.3), подлежит измерению; **v1** — детектор, дообученный на
накопленной разметке; далее без смены интерфейса.

### 8.1 Инструментарий

- **производственный цикл** — собственный интерфейс оператора (этап 3), единый для
  ректификации, измерения, правки и подтверждения предложений. CVAT здесь неприменим: в нём нет
  ни метрического масштаба, ни обратимой связи через `H`, ни механизма предложений, а два
  интерфейса исказили бы метрику трудозатрат;
- **массовая разметка обучающих данных** (этап 7), где метрика не нужна, — CVAT с
  SAM-ассистированием и экспортом в COCO. Он же служит базовым уровнем для вклада 3.

### 8.2 Инструкция разметчику

Отсутствовала в редакции 2, при том что от неё зависит весь вклад 1. Документ фиксирует:
определение кромки `wall_plane` (п. 5.3), правила для случаев `surround` и `cladding_edge`,
порядок обхода контура, обращение с частично закрытыми проёмами, критерии отказа от разметки.
Меж-разметчиковая согласованность измеряется на подвыборке (не менее 50 проёмов, не менее трёх
разметчиков) и публикуется: без неё эталонная кромка в обучающих данных «плывёт» ровно на ту
величину, которую вклад 1 обещает устранить.

## 9. Роль ректификации

Уточнено по итогам рецензии. Ректификация в настоящей работе — **метрологическая
необходимость, а не способ улучшить детекцию**: без неё не существует плоскости, в которой
миллиметры определены. Утверждать, что она улучшает качество детекции, нельзя: Facade R-CNN
показал обратное на RueMonge2014 (70.37 → 69.01 mIoU), Texture2LoD3 — противоположное.

Следствия, ради которых она первична:

- клик оператора и предсказание модели становятся величинами одного типа;
- выравнивание по рядам сводится к сравнению координат;
- масштаб в плоскости стены выражается одним числом (с поправкой раздела 5 для заглублённых
  элементов и с учётом того, что локальный GSD остаётся функцией положения в кадре);
- накопленная разметка не обесценивается при смене детектора.

Открытый вопрос, выносимый в эксперимент (вклад 2): где точнее **измерять** — в
ректифицированном изображении или в исходном с переносом результата. Все известные сравнения
оценивали качество сегментации, а не метрическую точность.

## 11. Данные

### 11.1 Основной контрольный объект

Снимаются **не менее 4 фасадов**, дающих не менее 150 проёмов с эталоном:

- съёмка с дрона при локальном GSD 3–5 мм/px;
- контролируемые серии по θ_cam: 0°, 15°, 30°, 45° — по горизонтали и по вертикали отдельно,
  поскольку компоненты угла входят в формулу глубины независимо (п. 5.4);
- серии по GSD и по выдержке (фактор смаза);
- **обязательно** фасады с заглублёнными проёмами разной глубины, хотя бы один с выступающими
  элементами и хотя бы один с обрамлениями (`edge_type: surround`);
- **дополнительно облёт с перекрытием** тех же фасадов для базового уровня SfM (п. 12.2). В
  редакции 2 этот облёт не был запланирован при наличии зависящего от него эксперимента.

### 11.2 Эталон: кромка и глубина

Эталон — наземное лазерное сканирование либо тахеометрическая съёмка.

**Эталон кромки.** Процедура описывается явно: подгонка плоскости стены, подгонка плоскости
откоса, пересечение — в соответствии с п. 5.3. Повторяемость измеряется (два оператора × два
прохода), вычисляется σ_ref.

**Эталон глубины.** Отдельная и более трудная задача, отсутствовавшая в плане редакции 2 при
наличии зависящего от неё главного эксперимента. Глубина определяется как расстояние между
подогнанной плоскостью стены и плоскостью ребра четверти (`datum: quarter_edge`). Трудность:
откос шириной 65–150 мм наблюдается с наземных станций под скользящим углом, на верхних этажах
точек может не хватить для подгонки плоскости. Поэтому:

- станции размещаются с учётом видимости откосов, при необходимости с подъёмом прибора;
- достижимая σ для глубины оценивается **до** начала основного эксперимента;
- проёмы, где σ не достигает требуемого, исключаются из выборки по глубине с указанием доли.

**Требование к соотношению.** TUR определяется корректно: TUR = T / (2U), где U = 2σ_ref —
расширенная неопределённость. При допуске ±20 мм требование TUR ≥ 3 даёт **σ_ref ≤ 3.3 мм**. В
редакции 2 требование было ослаблено до 7 мм без оговорки. Если на верхних этажах это
недостижимо, валидация ограничивается проёмами, удовлетворяющими условию, и доля таких проёмов
публикуется.

### 11.3 TUM2TWIN: вспомогательная роль

Проверка первоисточника (документация набора, Zenodo 14548134) показала, что снимки БПЛА
TUM2TWIN не соответствуют целевому сценарию:

- съёмка велась встроенной камерой **лидарного** сенсора Zenmuse L2 на DJI Matrice 350 RTK:
  «Photographs were simultaneously taken by the integrated camera of the Zenmuse L2 sensor,
  which is used to colorize the laser scans and to perform photogrammetric reconstruction of
  the scene»;
- основные миссии — надирные на 75 м; ручные проходы вдоль фасадов выполнялись «to reduce gaps
  in the data»;
- средний GSD снимков **1.6 см** — втрое хуже требования п. 2.2;
- опубликовано 962 снимка из 1104 (удалены кадры с людьми и номерами);
- расхождение фотограмметрического облака с лидарным: среднее 1.7 см, СКО 22.8 см.

Кроме того: TLS-съёмка выполнена 5 апреля 2024, съёмка с БПЛА — 17 декабря 2024; на сайте
набора указано, что TLS требует смещения на 0.7551 м по Z для согласования с моделями; число
зданий с LoD3 не документировано ни в статье, ни на сайте, ни в открытом репозитории.

Характеристики TLS (99 станций, MAE привязки 1.2 мм, абсолютная точность 7.1 мм) подтверждены,
но относятся к **привязке сканов**, а не к точности извлечения кромки из облака.

Роль набора: проверка семантики и состава элементов, эксперимент по поведению метода на грубом
GSD, задача переноса домена. Основой цифр точности он не является.

Резерв: TUM-FAÇADE (33 размеченных фасада и ~333 млн точек в расширенной версии на GitHub;
в исходной публикации 14 фасадов и ~118 млн точек, 17 классов), ZAHA (66 фасадов, 601 млн
размеченных точек, WACV 2025), RueMonge2014 (428 мультивидовых снимков с облаком и мешем).

### 11.4 Обучающие данные

Претрейн — публичные наборы: CMP (378 изображений в базовой части и 228 в расширенной, всего
606; 12 классов; величина «689 фасадов» получена после нарезки по фасадам в arXiv 2604.09260 и
цитируется по этой работе, а не по авторам набора), ECP (104), Facade-WHU, BFA-3D (синтетика).
Основная выборка — разметка, накопленная оператором.

Разделение выборок **по зданиям**, а не по снимкам, чтобы исключить утечку через разные кадры
одного фасада. Контрольный объект п. 11.1 в обучении не участвует ни на каком этапе.

## 12. Метрики и протокол

### 12.1 Метрики

| Группа | Метрика |
|---|---|
| Геометрия | RMSE и P95 габаритов; **bias отдельно от разброса**; абсолютное и взаимное положение отдельно |
| Глубина | Ошибка `recess_mm` против эталона как функция θ_⊥; доля проёмов с успешной оценкой; согласие каналов «откос» и «тень» |
| Детекция | precision, recall, mAP@0.5 по классам |
| Регулярность | SVD-метрика (arXiv 2604.09260), с оговоркой п. 3.4; не как единственная |
| Трудозатраты | время на фасад; число правок; доля `auto_confirmed` |
| Повторяемость | внутри- и межоператорская σ клика; меж-разметчиковая согласованность (п. 8.2) |
| Робастность | деградация по θ_cam, по GSD, по смазу, по `edge_type` |
| Неопределённость | покрытие, острота, proper scoring rule — п. 12.3 |

### 12.2 Базовые уровни

1. **Ортомозаика SfM** по облёту тех же фасадов (Metashape или Pix4D). Первый вопрос
   рецензента: «дрон уже облетел здание — почему не измерить по ортофотоплану?» Возможен исход,
   при котором SfM окажется точнее и быстрее; тогда работа должна заранее указать, где одиночный
   кадр оправдан: отсутствие облёта, аварийная или разовая съёмка, архивные снимки, участки,
   недоступные для полёта с перекрытием.
2. **Оператор в CAD** — существующий производственный процесс. Определение фиксируется:
   тот же контрольный объект, та же кромка `wall_plane`, то же число проёмов, оператор той же
   квалификации. В редакции 2 в разных разделах фигурировали «без автоматики» и «в CAD» как
   одно и то же.
3. **SAM-ассистированная разметка в CVAT** — базовый уровень для вклада 3.
4. **Детектор с alignment-loss без предварительной ректификации** — для вклада 2.

### 12.3 Калибровка неопределённости

Формулировка редакции 2 была неизмерима. Уточнённый протокол:

- покрытие на уровнях 1σ и 2σ с целевыми 68.3 % и 95.4 %. Уровень 3σ **не проверяется**: при
  доступном числе фасадов он статистически неразрешим;
- **декомпозиция по корреляции.** Ошибка масштаба общая для всех элементов фасада, поэтому:
  общая компонента оценивается отдельно по фасадам (не менее 4 значений), а покрытие по
  элементам вычисляется после её вычитания. Это снимает противоречие редакции 2, где покрытие
  агрегировалось по фасадам при их числе 4 и гранулярности 25 %;
- **острота**: средняя заявленная σ. Покрытие тривиально накручивается завышением σ, поэтому без
  остроты оно бессмысленно;
- proper scoring rule: гауссов NLL либо interval score; reliability diagram;
- систематические смещения оцениваются и сообщаются отдельно: при ненулевом bias калибровка σ
  может формально выглядеть корректной, оставаясь бесполезной.

### 12.4 Ablation

- **коррекция параллакса включена и выключена** — основной эксперимент работы;
- **скалярная и векторная формулы глубины** — демонстрация величины эффекта (п. 5.4);
- источник масштаба: оператор / EXIF / высота этажа;
- тип кромки: `sharp_wall_edge` / `surround` / выступающие;
- канал глубины: только откос / только тень / слияние;
- фокусное расстояние: калиброванное против EXIF;
- калибровка дисторсии включена и выключена;
- регуляризация: отсутствует / предложения оператору / автоматическая. Автоматический режим
  реализуется только для этого эксперимента (п. 4.3). Сравнение с предложениями ставится на
  одном операторе, с контрбалансировкой порядка и учётом эффекта обучения;
- **ректификация**: «в ректифицированном изображении» против «в исходном с переносом через H».
  Метрика — миллиметры, не mIoU. Метрика регулярности в варианте без ректификации неприменима и
  не сообщается.

### 12.5 Выборки и предрегистрация

Фиксируются **до** начала экспериментов: не менее 4 фасадов, не менее 150 проёмов с эталоном, не
менее 4 серий по углу на фасад, не менее 3 операторов, не менее 50 проёмов и 3 разметчиков для
согласованности. Одновременно фиксируются проверяемые гипотезы и критерии успеха и провала —
протокол предрегистрируется внутри проекта до получения данных.

### 12.6 Воспроизводимость

Фиксируются: сиды, версии моделей и весов, хэши наборов данных (DVC либо аналог), конфигурации
экспериментов, версия ПО в каждом выходном файле. Скрипт численной проверки раздела 5 включён в
регрессионные тесты.

## 16. Требования к производительности

Отсутствовали в редакции 2. Целевые значения:

- геометрический конвейер (`io` … `rectify`) на снимке 20 Мп: **≤ 15 с** на рабочей станции без
  GPU;
- предразметка `detect` v0: ≤ 30 с на кадр с GPU уровня RTX 4070;
- отклик интерфейса оператора на правку контура: ≤ 100 мс;
- пересчёт предложений регуляризации после правки: ≤ 1 с на фасад из 100 элементов.

Требования проверяются на этапе 3 и входят в критерий приёмки интерфейса.

## 17. Признанные ограничения

Перечень случаев, в которых метод неприменим либо применим с оговорками. Отсутствовал в
редакции 2; для статьи это обязательный раздел.

| Случай | Статус |
|---|---|
| Зеркальное и сильно отражающее остекление | **Вне объёма.** Отражения неба и соседних зданий создают ложные кромки и ложные «откосы»; сплошные стеклянные фасады ломают детекцию отрезков |
| Навесные вентилируемые фасады и системы наружного утепления | **Вне объёма для измерения глубины.** Плоскость облицовки не совпадает с плоскостью проёма, откосы металлические, часто с развёрткой; детекция работает, `recess` помечается `unavailable` |
| Скошенные («развёрнутые») откосы | Выявляются проверками п. 5.8, помечаются `suspect`; измерение глубины не производится |
| Арочные, круглые, треугольные проёмы, эркеры, угловые окна | **Вне объёма очереди 1**: схема допускает только четырёхугольник. Требует расширения геометрии элемента |
| Ложные окна, ниши, вентиляционные решётки, нарисованные проёмы | Известный источник ложных срабатываний; отдельного решения нет, выявляется оператором |
| Остеклённые лоджии (проём за проёмом на разных глубинах) | Двойной параллакс; `recess` помечается `suspect` |
| Несколько плоскостей в кадре (угол здания, эркер, ризалит) | Обрабатывается как несколько фрагментов; автоматическое разделение плоскостей не реализуется |
| Наклонные и криволинейные стены | Вне объёма |
| Загораживание растительностью, проводами, лесами, балконами верхних этажей | Влияет на `plane`, детекцию и эталон; частично закрытые проёмы размечаются по правилам п. 8.2 |
| Фасад в самозатенении | Канал тени недоступен; работает только канал откоса |

## 18. Режим облёта

Формулировка редакции 2 («меняются только два модуля») была неверна. Честный перечень:

| Затрагивается | Характер изменения |
|---|---|
| `plane`, `scale` | Замена на фотограмметрический бэкенд (SfM/MVS) |
| `rectify` | Ортомозаика фасада вместо warp одного кадра |
| Новый модуль слияния детекций | Один элемент наблюдается на нескольких снимках — модуля нет |
| `annotate` | Согласованность правок между кадрами |
| Модель погрешности (раздел 6) | Из уравнивания сети, а не из цепочки одиночного снимка |
| `io` | Набор снимков с позами |
| `depth` | Глубина из многовидовой геометрии; методы раздела 5 становятся запасными |
| Схема данных | **Уже рассчитана**: `images[]`, `pose_to_facade`, `contour_px` с привязкой к снимку |

Ядро — система координат, определение кромки, формат выхода, интерфейс оператора — переживает
переход без изменений; геометрический бэкенд заменяется целиком.
