# Веб-интерфейс оператора: дизайн

**Дата:** 2026-09-30. **Редакция 2** — после независимой рецензии (25 находок, из них 5 критических;
все проверены по коду и приняты, журнал — в конце). Реализация — по плану
`docs/superpowers/plans/2026-09-30-web-operator-interface.md`.

## 1. Зачем

Интерфейс оператора (план 3) — окно PySide6. В Docker оно работает на виртуальном экране и
показывается в браузере через noVNC: это удалённый рабочий стол, а не веб-интерфейс. Заказчик:
«всё как-то запутано в интерфейсе и не понятно, нужно сделать понятный и современный интерфейс».

Причины запутанности, найденные разбором `ui/window.py` и `ui/panels.py`:

1. **Пять панелей сразу** (плоскость, качество, база, проёмы, результат) в одной колонке с
   прокруткой — не видно, с чего начать и что сейчас главное.
2. **Скрытые режимы клика.** Что делает клик по кадру, определяет режим на панели инструментов;
   режим меняется кнопками на панелях, а сообщается мелкой надписью в строке состояния.
3. **Кнопки «Применить …»** там, где пересчёт стоит миллисекунды (масштаб, модель).
4. **Файлы — через диалоги Qt** в виртуальном экране: снимки класть в `./data`, сессию сохранять
   вручную, каталог экспорта выбирать.
5. **noVNC:** задержка картинки, фиксированный размер экрана, нет пароля.

## 2. Решения заказчика (2026-09-30)

| Вопрос | Решение |
|---|---|
| Программа или веб | **Веб-интерфейс** в браузере |
| Где работает | **У каждого оператора на своём компьютере** (`localhost`), без входа и многопользовательности; не закрывать путь к общему серверу позже |
| Судьба окна Qt | **Заменить полностью**: Qt-окно, noVNC и их тесты удаляются; демо, протокол σ клика и документация переводятся на веб |
| Технология | **FastAPI + страница на HTML/CSS/JS без сборки** (Node.js не нужен) |
| Детали | На усмотрение исполнителя: «главное, чтобы было понятно интуитивно и работало» |

Это отступление от п. 15 исходной спецификации («десктоп ради полноразмерных снимков без сетевых
задержек»): на `localhost` сети нет, кадр передаётся один раз, а масштаб, панорама и перетаскивание
идут в браузере без обращения к серверу.

## 3. Инварианты (переносятся без изменений или уточняются явно)

- **Логика — в `ui.session.OperatorSession`** (Qt-free), файл сессии — `ui.session_file`
  (формат и версия прежние), трудозатраты — `ui.labour`, σ клика — `ui.zoom`. Геометрии у веб-слоя
  нет. Добавления в сессию — только то, что нужно новому пути (перенос конца базы).
- **Показывается `Frame.color` без потерь**: кадр отдаётся PNG (сжатие 1), кодируется один раз
  в фоне вместе с фазой кадра и хранится байтами. JPEG — только для миниатюр и выровненного вида.
  Причина: у контрастной кромки JPEG даёт звон и смазанную цветность (4:2:0) ровно там, куда
  целится оператор при 4:1, и замер σ кромки (задача 25) шёл бы по другой картинке.
- **Соглашение о пикселях:** пиксель кадра `i` на экране занимает `[i, i+1)`; точка кадра =
  точка на кадре − 0.5, прижатая к `[0, w−1]`; нажатие вне снимка — не точка.
- **Масштаб просмотра** (`ClickedPoint.view_scale`) — **физических пикселей экрана на пиксель
  кадра**: масштаб холста в CSS-пикселях × `devicePixelRatio`. Так «1:1» — ровно пиксель в пиксель
  на мониторе при любом масштабе Windows и зуме браузера, а σ_экрана модели `ui.zoom` — промах в
  физических пикселях. Холст рисуется в физических пикселях (backing store × DPR), при масштабе
  ≥ 1 без сглаживания. Ctrl+колесо и жест «щипок» над кадром масштабируют кадр, а не страницу.
  Если DPR ≠ 1, в строке состояния — пометка «экран {DPR·100} %: масштабы — в пикселях монитора».
  (Окно Qt писало логические пиксели; при масштабе Windows 100 % это одно и то же. Протокол σ
  клика ещё не начат — определение фиксируется до сбора и вписывается в протокол.)
- **Фиксированные масштабы 1:2, 1:1, 2:1, 4:1 и «вписать»** — кнопки и клавиши `5 1 2 4 0`
  (протокол σ клика требует номинальных масштабов). Колесо — шаг 1.25, якорь под курсором,
  пределы 1:64 … 32:1. Изменение размера окна масштаб не меняет (вписывание — только по команде
  и при открытии кадра).
- **σ клика** считается одной формулой `ui.zoom.sigma_image_px`; сервер отдаёт её параметры
  (`SIGMA_SCREEN_PX`, `SIGMA_EDGE_PX`, `RECOMMENDED_MIN_SCALE`) в состоянии, строка состояния
  страницы показывает σ текущего масштаба по ним; тест сверяет число страницы с `zoom.py` на
  контрольных масштабах (функция в отдельном модуле `sigma.js`, тест — запуском через
  `node`, если он есть, иначе сверкой констант, выданных `/api/state`).
- **Выровненный вид — только просмотр** (п. 6.5): клик по нему центрирует кадр, точкой не
  становится; непокрытая часть растра — штриховка; контуры проёмов переносятся на растр по `H`.
- **Пересчёт после правки — полный** (без покомпонентного кэша, задача 16).
- **Правка — перенос целиком**: во время перетаскивания точка движется только в браузере; на
  сервер уходит одно отпускание. Отпускание со смещением ≤ 3 экранных px — не правка: ни
  события `edit`, ни пересчёта.
- **Захват точки для правки выключен, пока идёт постановка точек** (как в окне Qt: правка только
  в «Навигации»): иначе первая точка кромки откоса в нескольких пикселях от угла проёма
  «схватит» угол.
- **Тексты** — те же строки, что в выходном файле: причины `quality.reasons`, **вердикты словами
  ядра** `ok` / `degraded` / `reject` (цвет плашки по ним), тексты панели результата
  (`tolerance_text`, `RECESS_ORIGIN_TEXT`, `CALIBRATION_TEXT`, `POSITION_SIGMA_PENDING`,
  `NO_NEIGHBOUR_TEXT`) — переносятся из `ui/panels.py` в Qt-free `ui/texts.py`. Сохраняются и
  тексты строки состояния окна: «поворот на полкруга: задан оператором / не разрешён, принят
  «снимок не перевёрнут»», «пригодно по углу N % кадра»; по каждому концу базы — «σ клика … px»
  с пометкой о грубом масштабе; цена масштаба (`_warn_scale`) — после каждого угла, точки откоса
  и переноса.
- **Смена профиля калибровки при указанных точках** — только с явным подтверждением сброса.
- **Экспорт** — та же `session_file.export`: JSON, `marks.json`, DXF, `command.txt`, побайтная
  воспроизводимость через CLI.
- **Метка оператора** — см. п. 4.7.

## 4. Пользовательский путь

### 4.1. Экран «Снимки» (стартовый)

- Зона «Перетащите снимок сюда или выберите файл» (jpg, jpeg, png, tif, tiff). Загруженный файл
  сохраняется в `<рабочая папка>/снимки/`. Если файл с тем же sha256 уже есть в рабочей папке —
  открывается существующий; при совпадении имени — суффикс `_2`, `_3`, …
- Карточки всех снимков рабочей папки (рекурсивно; служебные папки `экспорт`, `.thumbs` и
  скрытые пропускаются) по папкам, с миниатюрой и статусом: **Новый** / **В работе** (есть файл
  сессии) / **Выгружен** (экспорт новее сессии) / **Изменён после выгрузки** (сессия новее
  экспорта). Миниатюры — лениво, кэш в `<рабочая папка>/.thumbs/` по пути, размеру и mtime.
- Если у двух снимков одной папки совпадает основа имени (`a.jpg`, `a.png`), у обоих пометка
  «одинаковое имя — переименуйте один»: файлы сессии и экспорта строятся по основе и
  перезаписали бы друг друга; такой снимок не открывается.
- Рабочая папка: `--data-dir`, по умолчанию `./data` (в Docker — `/data`).

### 4.2. Рабочий экран

```
┌ ← Снимки │ 01_фасад.jpg  ● сохранено │ ①Снимок ─ ②Масштаб ─ ③Проёмы ─ ④Результат │  ⋯ ┐
├──────────────────────────────────────────────────────┬─────────────────────────┤
│  [Снимок | Выровненный вид]                           │  Панель ТЕКУЩЕГО шага:  │
│                                                      │  — что сделать (1–2     │
│         кадр (canvas): масштаб, панорама,             │    фразы)               │
│         разметка, пригодная зона                      │  — поля шага            │
│                                                      │  — результат шага       │
│   ┌ «Кликните угол проёма w_000: 2 из 4» ┐            │                         │
│   └──────────────────────────────────────┘            │  [Главная кнопка]       │
├──────────────────────────────────────────────────────┴─────────────────────────┤
│ [1:2][1:1][2:1][4:1][⤢] │ 2:1 · σ клика 1.29 px │ x 1234 y 567 │ статус         │
└────────────────────────────────────────────────────────────────────────────────┘
```

- **Шаги наверху**: где ты, что сделано (✓), что требует внимания (!). Переход между шагами
  свободный, кроме шагов без кадра; главная кнопка ведёт к следующему.
- **Постановка точек** — единственное, что делает клик по кадру, и она всегда названа:
  подсказка поверх кадра «Кликните …: k из n» с кнопкой «Готово/Esc». Когда постановки нет,
  подсказка говорит, как двигать кадр и править точки. Что включает постановку — по шагам ниже.
  Незавершённая постановка при переходе на другой шаг сохраняется (точки остаются) и
  продолжается при возврате.
- **Мышь:** нажатие и отпускание со смещением ≤ 3 px — клик; перетаскивание по кадру — панорама;
  перетаскивание точки (радиус захвата 8 экранных px) — правка, только вне постановки и только
  точек текущего шага. Средняя кнопка или пробел + мышь — панорама всегда.
- **Автосохранение** после каждого изменения — `<основа>.session.json` рядом со снимком (имя по
  умолчанию окна Qt; там же его ищет протокол σ клика). Запись атомарная (временный файл +
  `os.replace`, повтор при `PermissionError`). Статус в шапке: «● сохранено» / «сохраняется…» /
  красная плашка «Сессия не сохраняется: {причина}» с кнопкой «Скачать файл сессии».
- **Меню ⋯:**
  - «Сохранить копию сессии…» — в папку внутри рабочей (по умолчанию
    `повторы/<метка оператора>/`) под именем `<основа>.<ГГГГММДД-ЧЧММСС>.session.json`: так
    собираются повторы протокола σ клика (`--repeat-dir`);
  - «Начать заново» — с подтверждением; прежняя сессия переименовывается в
    `<основа>.session.json.<ГГГГММДД-ЧЧММСС>.bak` (не теряется и не попадает под
    `*.session.json`);
  - «Профиль камеры…» (то же, что в шаге ①), «Скачать файл сессии», «Горячие клавиши».
- **Клавиши** (не действуют, когда фокус в поле ввода): `1` 1:1, `2` 2:1, `4` 4:1, `5` 1:2,
  `0` вписать; `Esc` — закончить постановку; `Ctrl+Z` — отменить последнюю точку проёма
  (шаг ③); `?` — справка.

### 4.3. Шаг ① «Снимок»

- Сведения: размер, поворот EXIF, камера (`CALIBRATION_TEXT`), поворот на полкруга.
- **Профиль камеры:** выпадающий список профилей из `<рабочая папка>/профили/` (и `*.json` в папке
  снимка, которые читаются `calib.load_profile`), «Загрузить профиль…», «Без профиля». При
  указанных точках — диалог «Профиль сдвигает кадр… Сбросить разметку и продолжить?».
- **Плоскость:** «Найдена автоматически, доверие 0.87» либо «Не найдена — укажите вручную» (тогда
  сразу включается постановка 4 углов). Действия (взаимоисключающие постановки):
  - «Задать вручную» → постановка 4 углов прямоугольника (порядок не важен) → доопределение
    (отношение сторон / два размера, мм / камера откалибрована) → «Применить плоскость»;
  - «Обвести область» (для снимка угла здания) → постановка ≥ 3 точек → «Оценить по области»;
  - «Вернуть автоматическую».
  После новой плоскости, если база готова, масштаб, растр и модель пересчитываются сами (точки
  при смене плоскости остаются верными — пиксели сдвигает только профиль).
- **Качество (предварительно):** плашка вердикта словом ядра, причины, «пригодно по углу N %
  кадра»; непригодная по углу часть кадра затемнена.
- Главная кнопка: «Далее: масштаб».

### 4.4. Шаг ② «Масштаб»

- Постановка включена, пока концов меньше двух: «Кликните первый конец опорной базы (он же начало
  отсчёта)», затем второй. Потом концы перетаскиваются; «Указать заново» — сброс и новая
  постановка. Третьего клика нет (в Qt третий клик начинал базу заново — здесь это кнопка).
- Поля: длина базы, мм; погрешность длины, мм (необязательно); происхождение (измерена / типовая
  высота этажа); «Первый конец — левый нижний угол фасада». По концам — «σ клика … px» и пометка
  о масштабе грубее 1:1, как в окне Qt.
- **Без кнопки «Применить»:** значение поля фиксируется по Enter, уходу из поля или 1 с покоя;
  пустое или неположительное — «длина не введена», масштаб не считается. Масштаб
  пересчитывается при каждом фиксированном изменении и при переносе конца. Результат: σ масштаба
  в % и в мм на базе, достигает ли допуска п. 6.3, начало отсчёта; **окончательный вердикт**
  плашкой с причинами и пояснением окна Qt.
- После масштаба в фоне строится выровненный вид (вкладка «Выровненный вид»).
- Главная кнопка: «Далее: проёмы».

### 4.5. Шаг ③ «Проёмы»

- «+ Окно» / «+ Дверь» создают проём и включают постановку 4 углов. Установка и тип кромки
  нового проёма — как у предыдущего созданного (в окне Qt списки тоже сохраняли выбор), у первого
  — значения по умолчанию сессии; у выбранного проёма они **всегда видны** в карточке, а после
  4-го угла подсказка просит их проверить: от типа кромки зависит, выпускается ли признак допуска.
- Список проёмов — карточки: id, класс, «углы 4/4», «откос: левая 2/2» и, когда модель
  посчитана, **ширина × высота ± σ**. Клик по карточке или внутри контура на кадре (вне
  постановки) выбирает проём. Выбранная карточка: установка, тип кромки, грань откоса (видимая
  грань по позе выбрана сразу, текст подсказки п. 5.5), «Разметить откос» (постановка 2 точек;
  смена грани при уже поставленных точках сразу стирает их, с пометкой), «Отменить точку»
  (`Ctrl+Z`), «Удалить».
- `Esc` во время постановки углов проёма с 0 углами удаляет пустой проём, иначе оставляет его
  незавершённым (он виден в причинах «углов k из 4»).
- **Модель пересчитывается сама** после каждого изменения, когда `ready_to_measure()`; иначе
  причины списком под проёмами.
- Главная кнопка: «Далее: результат».

### 4.6. Шаг ④ «Результат»

- Шапка: начало координат, камера, вердикт (тексты `ResultPanel`).
- Таблица: id, ширина, высота, положение X/Y, заглубление, θ, допуск — строки `ResultPanel`;
  наведение на строку подсвечивает проём на кадре.
- **«Выгрузить JSON и DXF»** → `<папка снимка>/экспорт/` (имя ждёт `scripts/training_blocks.py`
  и `docs/operator-training.md`): список файлов со ссылками «Скачать», строка команды CLI с
  «Копировать».

### 4.7. Метка оператора

- `--operator op-xxxxxxxx` / `FACADE_OPERATOR` — **явная** метка; без неё — случайная на запуск.
- Новая сессия получает метку сервера. При восстановлении сессии из файла:
  - метка сервера случайная → продолжается метка файла (как у окна Qt при «Открыть сессию»);
  - метка явная и совпадает → продолжение;
  - метка явная и другая → вопрос «Сессия начата оператором op-a. Продолжить под меткой op-b
    (время op-a останется в сумме) или начать заново?»; без ответа снимок не открывается.

## 5. Архитектура

```
браузер (static: index.html, styles.css, app.js, viewer.js, api.js, sigma.js)
   │  HTTP/JSON, заголовок X-Facade-Token, rev/desk в каждом изменении
   ▼
web/app.py      FastAPI: маршруты, проверка Host и токена, 409 при устаревшей ревизии/занятости
web/workbench.py  Workbench (рабочая папка, список снимков, текущий Desk)
                  Desk (OperatorSession + экран: шаг, постановка, выбранный проём, растр,
                        байты кадра, ревизия) → state()
   ▼
ui/session.py, ui/session_file.py, ui/labour.py, ui/zoom.py, ui/texts.py, pipeline.run
```

### 5.1. Сервер

- **`web/workbench.py`** — перенос логики `MainWindow` без Qt и без HTTP: `Desk.click(x, y,
  view_scale)` по текущей постановке, `drop(key, x, y, view_scale)`, операции шагов, профиль,
  пересчёты, автосохранение и `state()` — словарь JSON со всем, что рисует страница: шаги и
  статусы, постановка и подсказка, наложения (точки и контуры в координатах кадра, цвета,
  ключи точек, которые можно тащить), тексты панелей, таблица результата, `H` и размеры растра,
  параметры σ, статус сохранения, `busy`. Страница геометрию не считает — только переводит
  экран ↔ кадр и рисует.
- **Ревизия и адресация.** У `Desk` — `desk_id` (sha256 снимка + номер открытия) и `rev`
  (растёт с каждым изменением). Каждый изменяющий запрос несёт оба; несовпадение → `409` с
  текущим `state()`; страница применяет его и сообщает «действие не выполнено: состояние
  изменилось». Страница шлёт изменения строго по одному (очередь) и отбрасывает ответы с
  `rev` ниже применённого. `state()` кэшируется по `rev`.
- **Долгие фазы** (кадр — до 4 с с PNG, растр — до 4 с) — в пуле потоков, с номером поколения:
  результат устаревшего поколения отбрасывается (семантика `ui.worker`). Пока идёт фаза кадра,
  `busy` = текст, изменения → `409`, страница затемняет кадр с индикатором; версия кадра в URL
  (`/api/frame.png?v=`) меняется с каждым новым `Frame` (в том числе после смены профиля).
  Страница опрашивает `/api/state` раз в 400 мс, только пока есть `busy` или растр в работе.
- **Изображения:** `GET /api/frame.png` (байты из памяти), `/api/usable.png` (маска 64×64 RGBA,
  растягивается со сглаживанием), `/api/rectified.jpg` и `/api/rectified_mask.png`,
  `/api/thumb?path=`, `/api/export/<файл>` (скачивание), `/api/session/download`.
- **Безопасность localhost** (иначе любой сайт в браузере оператора шлёт `POST` на 127.0.0.1, а
  через DNS rebinding и читает ответы):
  1. заголовок `Host` ∈ {`localhost`, `127.0.0.1`, `[::1]`} с портом сервера, иначе `421`;
  2. изменяющие запросы — только с `X-Facade-Token` (случайный на запуск, вписывается в
     `index.html` при отдаче страницы); без него `403`. Форма чужого сайта заголовок не
     поставит, `fetch` с ним упрётся в CORS-preflight, которого сервер не разрешает;
  3. `--host` не loopback — отказ запуска (многопользовательский режим вне рамок).
  Пути из запросов принимаются только внутри рабочей папки (`resolve()` + проверка
  вложенности); загрузка — только расширения снимков и `.json` профиля, не более 200 МБ.
- **Один сервер на рабочую папку:** `<рабочая папка>/.facade-ui.lock` (pid, порт). При запуске,
  если по записанному порту отвечает `/api/ping` с той же папкой, — открыть браузер на нём и
  выйти; иначе захватить.
- **Запуск:** `facade-digitize-ui` → uvicorn на `127.0.0.1:8765` (следующий свободный, если
  занят), открывает браузер; `--no-browser`, `--port`, `--data-dir`, `--operator`.
- **Поиск файлов сессии (совместимость и переносимость).** `session_file.load_session`
  ищет снимок сначала по сохранённому пути, затем рядом с файлом сессии по имени; профиль — по
  пути, затем в папке сессии и в `<рабочая папка>/профили/`. Хэш остаётся защитой. Формат
  файла не меняется. Так открываются сессии окна Qt, сессии из Docker (`/data/…`) на хосте и
  папки обучения, перенесённые между компьютерами.

### 5.2. Страница
