# Меж-разметчиковая согласованность: протокол (предрегистрация)

План 3, задача 26; спецификация, п. 8.2 («не менее 50 проёмов, не менее трёх
разметчиков, результат публикуется») и п. 12.5. **Зафиксирован до сбора;
отступления — в конце, с датой и причиной.**

Статус: показатели и инструмент готовы; **выборка и сбор не начаты** — нужны реальные
снимки с обрамлениями и откосами (на синтетике выбирать нечего) и три обученных
оператора (задача 24).

## 1. Вопрос

Насколько разные обученные разметчики, работая по одной инструкции
(`docs/superpowers/specs/annotator-instruction.md`), дают одну и ту же разметку —
в миллиметрах по каждой кромке и в категориях, решающих выпуск признака допуска.

## 2. Показатели и почему именно они

| Показатель | Функция | Зачем |
|---|---|---|
| пределы согласия (Бланд — Альтман) по каждой кромке, мм: σ внутри проёма и ±1.96·√2·σ для любой пары | `metrics.limits_of_agreement` | разброс указания в единицах допуска |
| смещение каждого разметчика от среднего по проёму, мм | там же, `rater_bias` | выбивающийся разметчик виден, а не растворяется |
| каппа Флейса для `edge_type` и `mounting` | `metrics.fleiss_kappa` | через `edge_reference` они решают, выпускается ли `meets_tolerance` |
| доля проёмов без единодушия по `edge_type` | `metrics.disagreement_fraction` | то же, без поправки на случайность |
| доля расхождений в **выборе** кромки: кромка дальше 40 мм от медианы по разметчикам | `agreement_study.agreement_many` | рама вместо кромки стены (п. 5.3) — ошибка другого рода, чем промах указания |
| доля проёмов, пропущенных хотя бы одним | там же | пропуск — тоже расхождение |

**ICC не используется**: размеры проёмов различаются на метры, межпроёмная дисперсия
топит разметочную, и ICC ≈ 0.999 при любом качестве разметки.

Кромки всех разметчиков переводятся в мм **одной геометрией** — гомографией и масштабом
экспорта первого разметчика: каждый ставит свою базу, и различие баз не должно
смешиваться с различием разметки. Сравниваются пиксели кадра (`contour_px`).

Все показатели проверены на аналитически известных случаях:
`tests/test_agreement_metrics.py` (включая опубликованный пример Флейса, κ = 0.210) и
`tests/test_agreement_study.py` (известный шум, выбор рамы у одного разметчика,
пропуск проёма, несколько снимков со своей геометрией).

## 3. Выборка

- **Не менее 50 проёмов** на реальных снимках; не менее трети — с обрамлением или
  облицовкой (`surround`, `cladding_edge`), не менее трети — с видимой гранью откоса.
- Снимки: задача 20 (открытые источники, лицензия CC0/CC-BY, анонимизация) и/или
  снимки заказчика; список снимков и проёмов фиксируется в разделе «Выборка» ниже
  **до** начала разметки.
- Кадры `reject` в выборку не входят.

## 4. Процедура

- Три разметчика (не менее), обученные до критерия задачи 24, каждый со своей меткой.
- Каждый размечает все снимки независимо, в своём порядке (случайная перестановка
  снимков на разметчика, записывается), базу ставит сам по инструкции; углы — при
  2:1–4:1.
- Экспорт в `согласие/<метка>/` («Экспорт JSON и DXF…»).
- Разметчики не видят разметку друг друга до окончания сбора.

## 5. Анализ (зафиксирован до сбора)

```bash
python scripts/agreement.py согласие/op-… согласие/op-… согласие/op-…
```

Сообщаются все показатели раздела 2, отдельно по родам кромки (`sharp_wall_edge`
против остальных). Ожидание, по которому читается результат: σ внутри проёма по
кромке не больше σ клика задачи 25 при 2:1, пересчитанной в мм (≈ 1.3 px · GSD / √2);
превышение означает, что расхождения — не в указании, а в понимании правил
**[человек]** инструкции, и это отдельный вывод отчёта.

## 6. Публикация

Отчёт `docs/superpowers/plans/results/agreement-report.md` публикуется целиком,
включая неудобные результаты; данные разметки (JSON экспорта) — рядом, без имён.
