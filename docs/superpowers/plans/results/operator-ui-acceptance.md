# Приёмка интерфейса оператора (план 3, задача 19)

## Сделано автоматически

- `scripts/demo_ui.py` проходит весь путь чек-листа А (открыть → вердикт → база →
  проём с откосом → результат → правка → сессия → экспорт) без экрана. Снимки
  экрана каждого шага — `results/operator-ui/demo/01…07-*.png`. Итог на
  синтетическом фасаде (истина 1460 × 1900 мм, заглубление 150 мм):
  **1459.0 ± 14.2 × 1901.1 ± 14.8 мм, заглубление 157.2 ± 10.2 мм**.
  После сдвига угла на 12 px ширина — 1472.6 мм (снимок 06).
  Тест `tests/test_ui_demo_script.py` держит сценарий рабочим.
- `scripts/make_acceptance_inputs.py` — входные файлы сценариев Б–Д; проверено
  прогоном ядра:

  | Файл | Результат фазы кадра / модели |
  |---|---|
  | `01_фасад.jpg` + `профиль_DEMO-CAM.json` | K: target, доверие 0.80 |
  | `01_фасад.jpg` + `профиль_чужой.json` | отказ: «профиль калиброван на камере «OTHER-CAM», а снимок сделан камерой «DEMO-CAM»» |
  | `02_фасад_поворот_EXIF.jpg` | Orientation 6, кадр 5280 × 3956 (прямой), доверие 0.78 |
  | `03_фасад_далеко.jpg`, база 1460 мм | вердикт reject: «недостаточное разрешение: 6.5 мм/px > 5.0» |
  | `04_без_линий.jpg` | needs_operator; ручная плоскость по табличке 2:1 — manual_four_point |

- В окно добавлен пункт «Файл → Профиль калибровки…» / «Снять профиль калибровки»
  (сценарий Г требовал его, а окна без него не было): смена профиля при указанных
  точках — только с подтверждением, чужой профиль — отказ с названием камеры
  (`tests/test_ui_profile.py`).
