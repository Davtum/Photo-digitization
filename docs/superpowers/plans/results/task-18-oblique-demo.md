# Выравнивание косого снимка: «снимок под углом → фронтальный вид» (задача 18)

Демонстрация на снимке CMP (`task-18-cmp-demo.md`) не показывает **выравнивания**, и
показать его не может: CMP — набор уже ректифицированных фасадов (задача 17, раздел
«Точки схода на бесконечности»), охват маски там 99.4 %, а исходный и выровненный
растры на глаз различаются подрезкой краёв. То есть главный видимый результат ядра —
приведение косого кадра к фронтальному виду — в наглядных материалах отсутствовал.

Косой кадр у проекта есть **по построению**: синтетическая сцена
`tests/test_synth.py::make_scene` рендерится полной моделью камеры, перспектива и
параллакс в ней возникают сами (`facade_digitizer/synth/scene.py`). Ниже — тот же
самый кадр, на котором работают тесты стыка `run → elements`
(`tests/test_elements.py::_cli_scene`: `dx = 3000`, `dy = −2000`, `dist = 20000`,
проём с заглублением 150 мм), прогнанный через CLI целиком.

Артефакты — в `docs/superpowers/plans/results/task18-oblique-demo/`:

| файл | что это |
|---|---|
| `synthetic_oblique.png` | **исходный косой кадр**, 5280×3956 |
| `synthetic_oblique_rectified.png` | **выровненный растр**, 3229×2533 (`--save-rectified`) |
| `synthetic_oblique_rectified_mask.png` | маска охвата рядом с ним |
| `marks.json` | разметка проёма, подаваемая ключом `--marks` |
| `synthetic_oblique.json` | выход `facade-digitize` |

## Что видно на паре растров

На исходном кадре фасад — трапеция: его верхняя сторона длиннее нижней, а
межэтажные членения сходятся вправо, потому что камера смещена на 3 м вправо и 2 м
вниз от центра фасада. На выровненном растре те же членения **параллельны**, стена —
прямоугольник, и проём — прямоугольник. Это и есть перевод в метрическую систему
координат плоскости фасада; всё остальное в выходном файле считается уже в ней.

Охват маски — 85.2 % площади растра (против 99.4 % у CMP): косой ракурс оставляет в
прямоугольнике растра пустые углы, и маска называет их по имени, а не отдаёт
потребителю серый фон как измеренную часть фасада.

Наклон, восстановленный из того же кадра: `theta_cam_deg = 10.36°`, поза
`{cx: 13094.8, cy: 5442.7, cz: 20332.2}` мм при истинных `(13000, 5500, 20000)` —
расхождение 0.7…1.7 % и целиком объяснимо тем, что K берётся из типового поля зрения
(`camera.calibration = "database"`: снимок записан `save_image` и потому без EXIF),
а не из истинной матрицы сцены.

## Измерение по ИСХОДНОМУ снимку, а не по растру

Растр сохранён для просмотра оператором. Разметка проёма задана в координатах
исходного кадра (спецификация, п. 6.5; докстринг `pipeline/elements.py`), и результат
сходится с истиной сцены:

| величина | истина сцены | измерено | σ |
|---|---:|---:|---:|
| ширина проёма, мм | 1460.0 | 1459.6 | 16.4 |
| высота проёма, мм | 1900.0 | 1899.4 | 17.1 |

Угол визирования на сам проём — `θ = 24.86°` (`x_deg = −24.10`, `y_deg = −6.85`),
взятый в ХУДШЕЙ точке контура; σ масштаба — 0.18 %, то есть внутри диапазона
0.14–0.28 % п. 6.3, и `facade.scale.meets_tolerance = true`.

## Шлюз качества здесь срабатывает, и это видно в файле

```json
"quality": {
  "verdict": "reject",
  "gsd_mm_px_min": 4.89, "gsd_mm_px_max": 6.55,
  "reasons": [
    "недостаточное разрешение: 6.5 мм/px > 5.0",
    "вердикт reject: признак соответствия допуску (meets_tolerance) у элементов не выпускается — кадр не удовлетворяет требованию п. 2.2 к разрешению, и утверждать по нему соответствие тому же п. 2.2 нечем"
  ]
}
```

С 20 метров при f ≈ 3664 px один пиксель снимка стоит 5.5 мм на фасаде, а худшее
значение по пригодной области — 6.55 мм/px против порога 5. Кадр требованию п. 2.2 к
разрешению не удовлетворяет, поэтому `meets_tolerance` у элемента **отсутствует**
(`null`), хотя габарит и σ выпущены по-прежнему: отбраковка помечает, а не
уничтожает улику. Обоснование именно такого ветвления — в
`facade_digitizer/pipeline/run.py::GATE_REJECT_WITHHOLDS_TOLERANCE`; проверки —
`tests/test_elements.py::test_the_quality_gate_acts_on_its_own_verdict` и
`::test_the_quality_gate_withholds_the_claim_without_erasing_the_measurement`.

`edge_reference` при этом равен `"wall_plane"`, а не `"unknown"`, как на снимке CMP,
и это честно: кромка проёма синтетической сцены лежит в плоскости стены **по
построению сцены**, а не по догадке о фотографии из интернета.

## Воспроизведение

Кадр и разметка получаются из сцены проекта (`tests/test_synth.make_scene` с
умолчаниями `_cli_scene`), после чего вызывается обычный CLI:

```python
import numpy as np
from facade_digitizer.pipeline.io import save_image
from tests.test_synth import make_scene

sc = make_scene(dx=3000.0, dy=-2000.0, dist=20000.0, depth=150.0)
save_image("synthetic_oblique.png", sc.render())
# Опорные точки оператора: начало отсчёта — левый нижний угол фасада,
# опорная база — вся его нижняя сторона (20 000 мм).
print(sc.project(np.array([[0.0, 0.0], [20000.0, 0.0]])))
# Разметка: четыре угла проёма в координатах ИСХОДНОГО снимка.
print(sc.project(sc.openings[0].corners_mm()))
```

## Чего эта демонстрация НЕ показывает

Точности на реальных данных. Сцена синтетическая: геометрия в ней известна точно,
шума матрицы, дисторсии объектива и неплоскостности стены в ней нет вовсе, и
совпадение габарита с истиной до полуметра миллиметра — свойство сцены, а не
измерение по фотографии. Для реальных снимков есть `task-18-cmp-demo.md` и
`geometric-core-smoke.md`; там, наоборот, нет истинных размеров. Две демонстрации
дополняют друг друга и ни одна не заменяет натурных измерений с эталоном, которых у
проекта пока нет.
