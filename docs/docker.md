# Запуск в Docker: интерфейс оператора в браузере

Всё приложение — в одном контейнере: сервер интерфейса работает в контейнере, а
страница открывается **в браузере вашего компьютера**. Ставить Python не нужно —
только Docker.

## 1. Что нужно

- **Windows 10/11 или macOS** — [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  (запустить и дождаться «Engine running»).
- **Linux** — Docker Engine и плагин `docker compose`.
- Около 1.5 ГБ на диске под образ.

## 2. Первый запуск

```bash
git clone -b feature/geometric-core-hyc1rc https://github.com/Davtum/Photo-digitization.git
cd Photo-digitization
mkdir data
docker compose up --build
```

Первая сборка — несколько минут (скачиваются Python-пакеты и OpenCV). Когда в консоли
появится `Интерфейс оператора: откройте в браузере http://localhost:8765`, откройте
**http://localhost:8765**.

При первом запуске в `data/примеры/` появятся снимки для проверки и `ИСТИНА.txt` с
правильными размерами (сценарии — `docs/operator-acceptance-checklist.md`).

## 3. Свои снимки и результаты

Папка `data/` рядом с `docker-compose.yml` — рабочая папка интерфейса (внутри
контейнера это `/data`):

- **снимки** — перетащите в браузер на экране «Снимки» (сохранятся в `data/снимки/`)
  или положите в `data/` сами (можно в подпапки) — они появятся в списке;
- **сессии** пишутся сами рядом со снимком (`<снимок>.session.json`);
- **выгрузка** («Выгрузить JSON и DXF» на шаге «Результат») — в папку `экспорт/`
  рядом со снимком; файлы можно и скачать ссылками со страницы. DXF открывается в CAD.

Сессии переносимы: папку `data/` можно открыть и программой, установленной без
Docker (`facade-digitize-ui --data-dir data`), — снимок ищется рядом с сессией.

## 4. Автоматическая демонстрация

В `docker-compose.yml` поставьте `DEMO: "1"` и перезапустите — программа сама пройдёт
весь путь на синтетическом фасаде (база → проём → откос → расчёт → выгрузка в
`data/демо/`), и страница откроется на размеченном снимке.

## 5. Управление

| Что | Команда |
|---|---|
| остановить | `Ctrl+C` в консоли либо `docker compose down` |
| запустить снова (без пересборки) | `docker compose up` |
| обновить после `git pull` | `docker compose up --build` |
| в фоне | `docker compose up -d`, остановить — `docker compose down` |

## 6. Настройки (`docker-compose.yml`)

- `OPERATOR` — метка оператора `op-xxxxxxxx` для учёта трудозатрат (задача 22).
- `DEMO` — `1`, чтобы при запуске открыть готовую демонстрацию.
- Порт `8765` открыт только для этого компьютера (`127.0.0.1`): входа по паролю нет,
  и страница принимает запросы только с адреса `localhost`.

## 7. Если что-то не так

| Симптом | Решение |
|---|---|
| Linux: «Папка /data недоступна для записи» | `sudo chown -R 1000:1000 data`, затем `docker compose up` |
| страница не открывается | дождаться строки «откройте в браузере…»; проверить, что порт 8765 не занят |
| «сервер принимает запросы только с этого компьютера» | открывать `http://localhost:8765` или `http://127.0.0.1:8765`, не по имени компьютера |
| Windows: `facade-start: not found` | клон сделан с CRLF-окончаниями и старый образ; `docker compose build --no-cache` |
| после обновления страница ведёт себя странно | обновить страницу (F5) |
